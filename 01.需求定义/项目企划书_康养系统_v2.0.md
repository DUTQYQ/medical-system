# 1. 项目背景

中国老龄化程度持续加深，传统康养服务面临五大问题：

1. 老年用户不熟悉复杂互联网操作，使用门槛高；
2. 健康数据（血压 / 血糖 / 心率 / 睡眠 / 步数）分散，缺乏统一管理；
3. 老人出现异常体征后，家属无法及时获知；
4. 传统健康咨询只能关键词匹配，缺少上下文理解与个性化；
5. 健康数据与日常咨询之间缺乏关联，无法形成服务闭环。

**结论**：需要一个结合 AI 大语言模型的智能康养平台——采集健康数据 → AI 分析咨询 → 异常主动预警 → 家属 / 护工及时处理，形成完整闭环。

# 2. 项目目标

- **目标一 · 降低使用门槛**：适老化设计——【核心】大字号 ≥18~24px、高对比度、少层级、大按钮 ≥48px；【选配】语音输入 STT、语音播报 TTS
- **目标二 · 统一健康档案**：用户 → 档案 → 指标 → 历史记录 的完整数据体系（【核心】）
- **目标三 · AI 健康助手**：结合档案 + 历史数据 + 知识库（RAG），回答老人自然语言健康问题（【核心】）
- **目标四 · 主动预警机制**：后台持续分析健康数据，超阈值自动分级预警并推送家属 / 护工（核心卖点）
- **目标五 · 形成康养闭环**：数据采集 → AI 分析 → 咨询 → 异常检测 → 预警 → 家属 / 护工处理 → 处理记录（【核心】）

# 3. 用户角色（4 类）

| 角色 | 主要功能 |
|---|---|
| 老年用户 | 健康查看、AI 咨询、健康打卡、预警查看 |
| 家属用户 | 查看老人健康、接收预警、确认处理 |
| 护工 / 社区人员 | 管理多名老人、查看 / 处理预警 |
| 系统管理员 | 用户 / 角色管理、知识库管理、预警规则配置、AI 模型配置 |

# 4. 功能范围（含选配标注）

## 4.1 用户与权限管理【核心】

注册 / 登录（手机号 + 密码 + 格式校验）、JWT 鉴权、角色权限（老人 / 家属 / 护工 / 管理员）、【选配】忘记密码。

## 4.2 老人健康档案【核心】

基础信息（姓名 / 性别 / 生日 / 身高体重 / 血型 / 过敏史 / 病史 / 紧急联系人）、慢病标签、【选配】用药信息（药名 / 剂量 / 时间）。

## 4.3 健康数据监测【核心】

- 指标录入：血压、血糖、心率、睡眠、步数（统一健康记录表 + 类型字段）
- 健康趋势图：ECharts 近 30 天曲线，异常点高亮标注（【核心】）
- 【选配】健康打卡（每日血压 / 睡眠 / 运动一键打卡）、【选配】PDF 报告导出

## 4.4 AI 健康咨询【核心】

- 文本咨询（结合用户档案 + 近期数据 + 知识库）
- 意图识别路由（普通咨询 / 数据类问题 / 异常 / 紧急）
- RAG 知识库检索增强回答
- 【选配】语音咨询（STT 按住说话）、【选配】语音播报（TTS）

## 4.5 AI 健康预警【核心】

- 阈值规则引擎（阈值配置化，不写死）
- 风险等级判定（0 正常 / 1 轻度 / 2 较高 / 3 高风险）
- AI 生成个性化预警说明（结合历史趋势，非机械告警）
- 分级通知：老人端提醒 → 家属端 → 护工后台
- 预警处理闭环（待处理 → 已查看 → 已处理，留操作日志）

## 4.6 家属端【核心】

绑定老人、查看健康概况与趋势、接收 / 确认预警；【选配】健康日报 / 周报。

## 4.7 护工 / 社区管理后台【核心】

负责老人列表（正常 / 关注 / 异常状态一目了然）、预警管理、处理记录。

## 4.8 管理员后台【核心】

用户管理、角色管理、预警规则配置、健康指标配置；【选配】知识库管理（文档上传 → 解析 → 向量化）、【选配】AI 模型配置、【选配】系统日志。

## 4.9 健康知识库（RAG 数据源）【核心】

- 预置知识分类：高血压 / 糖尿病 / 心率异常 / 睡眠 / 老年运动 / 老年饮食 / 常见问题
- 检索流程：问题 → Embedding → 向量库 Top-K → Prompt → LLM（【核心】）
- 【选配】管理员在线上传文档自动建索引

## 4.10 选配增强包（明确为选配，答辩作扩展展示）

数字人形象交互（动画模型 + 关键字驱动）、PDF 健康报告导出、药物提醒、健康打卡、移动 APP 端（本期以 Web 为主，响应式适配手机）。

# 5. 技术方案

## 5.1 总体架构

前后端分离 + AI Agent 服务 + 数据库 + 知识库：

```
老人端(Vue, 适老化) / 家属端(Vue) / 管理后台(Vue)
          │ RESTful API (Axios)
后端服务层 (Python FastAPI)
 ├─ 用户/权限服务  ├─ 档案服务  ├─ 健康数据服务
 ├─ 预警服务      ├─ 家属服务   └─ 报告服务
          │
 ┌────────┼──────────────┐
MySQL 数据库   AI Agent 服务      Redis(缓存·选配)
              ├─ LangChain/LangGraph 编排
              ├─ LLM: Qwen/DeepSeek/GLM-4
              └─ RAG: 文档切分 → Embedding → 向量库
```

## 5.2 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Element Plus | 组件化，适老化样式自定义 |
| 图表 | ECharts | 趋势图、异常高亮（需求明确要求） |
| 后端 | Python FastAPI | AI 生态友好，开发效率高（已确认） |
| 数据库 | MySQL 8 | 结构化健康数据 |
| AI 编排 | LangChain / LangGraph | 多 Agent 流程编排 |
| 大模型 | 通义千问 / DeepSeek / GLM-4 | 按成本与可用性选 1~2 个 |
| RAG | Embedding + 向量库（Chroma/FAISS） | 知识库检索 |
| 语音（选配） | Web Speech API（STT / TTS） | 浏览器原生，零成本 |

## 5.3 Agent 架构（答辩核心）

```
START
 → 意图识别 Agent（普通咨询 / 数据问题 / 异常 / 紧急 路由）
    ├─ 普通咨询 → Health Agent（RAG 检索 + 个性化回答）
    ├─ 数据类   → Health Data Agent（查库 + 趋势分析 + 回答）
    ├─ 异常     → Risk Agent（风险分级 + 生成预警 + 通知）
    └─ 紧急     → Emergency Agent（建议就医 + 触发紧急通知）
Alert Agent（后台守护）：新数据 → 合法性校验 → 阈值检测 → 历史趋势 → 风险分级 → AI 预警摘要 → 通知家属/护工
```

## 5.4 AI 安全分级（L1~L4）【核心】

| 级别 | 场景 | 系统行为 |
|---|---|---|
| L1 | 普通咨询（每天走多少步） | 正常回答 |
| L2 | 健康建议（睡眠不好怎么办） | 生活方式建议 |
| L3 | 异常数据（血压 165/100） | 风险提示 + 建议就医 + 触发预警 |
| L4 | 紧急表述（胸痛 / 呼吸困难） | 不闲聊，立即建议求助 + 通知紧急联系人 |

> 页面固定免责声明："内容仅供参考，不构成医疗诊断。"

# 11. 一句话定位（答辩用）

> **"一个面向老年人的 AI 主动式健康管理平台"**——让老人能"说出来"，让 AI 能"听懂、分析、回答"，让系统能"主动发现问题"，让家属和护工能"及时处理"，形成完整康养闭环。而非"一个带 AI 聊天功能的养老系统"。
