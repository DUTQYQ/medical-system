## 关键行为与并发

首次问询按档案与模板唯一，逐题回答、跳过、刷新续答、确认前不形成事实。词条支持确认后补充、修改、撤销及版本留痕；来源消息不能跨档案引用。过期短期词条不进入当前建议。建议四分区展示，动作只预填，用户提交后才创建业务申请。

个体阈值待审核不生效，审核后仅影响指定档案的后续录入。测试验证同一指标值在两份档案使用各自配置，可产生不同等级；历史趋势与预警保持原检测快照，删除测量后预警证据仍保留。撤销负责关系的护工不能再提交或让旧申请获得批准。

MySQL 并发验收包含：同一预警处理只留一份结果、重复绑定只留一份申请、首次问询只创建一个实例、最后一个活动名额不超员、最后一件设备不超借、同一服务工单只接单一次。另验证已经建立旧查询快照的事务，在阈值审核或绑定撤销之后，写入路径仍读取当前生效规则与当前授权关系。

生活工单完成须填实际结果，通知已读不改变工单状态。呼叫不等待模型，也不依赖健康授权；重复点击复用未完成呼叫，无负责护工立即升级管理员。活动取消通知参与者并取消待出席报名，出席历史保留；名额取消后释放。设备库存不足时接单与出库整体回滚，重复归还不重复增加库存，损坏件不进入可用数量。

浏览器共四十四项检查实际执行了四角色页面和写操作，并检查无权限、网络失败及没有健康授权的新老人呼叫。三组页面运行错误列表均为空。最终版本复测异常录入、家属新通知、原阈值快照、处理留痕、趋势与统计 ECharts；管理员导航完整可见，建议默认展示最新一张、历史版本可选择，截图在无过渡遮罩和提示叠加的稳定状态采集。

## 原库迁移与交付保留

迁移使用 `scripts/migrate_v2.py`，先备份到后端忽略目录 `config.local.migration-backup`，再只创建缺少的扩展表。目前扩展表共十五张；原表未修改或重建。非演示初始化追加服务目录、呼叫超时、记录新鲜度及摘要请求额度配置，不覆盖既有配置，不在真实库生成演示业务记录。

早期首次迁移使用第一次备份逐行核对原十五张表的三十四行，`sys_config` 当时从十六行增加为十七行。2026-10-14 后续迁移前再次备份；本轮未新增表，仅追加三个可选摘要额度配置，既有业务数据保留。当前元数据共三十表。迁移守卫另验证完整结构通过、缺少问询唯一键拒绝。

已有 `.gitignore` 未修改，真实 `.env`、密码和 Key 不进入源码；原先用户已修改的《概要设计说明书 v2.0 模板版》保留，本轮没有编辑。没有提交或推送 Git。新的设计、运行与验收文档提供 Markdown 和 Word 双份。

## 验证限制

早期验收时模型 Key 未配置；用户后续已填写后端配置。2026-10-14 本轮使用当前配置完成一次不含个人资料的实际模型连通性测试，返回有效文本。真实模型多轮质量、医学安全性及持续调用成本仍未完整验收；回归测试使用明确的测试替身。哈希 Embedding 仍属于词形检索，真实语义模型未安装验收。

原 MySQL 的部分默认健康阈值缺少低值覆盖，本轮保留原配置；录入未覆盖值会明确返回配置错误，管理员需根据院方确认的规则补齐。个体阈值流程不能替代医护判断。

【选配】入住床位、完整排班、费用财务、硬件呼叫按钮、短信及电话外呼、损坏设备维修后恢复库存、完整临床知识库均未列为本轮完成项。本轮实现用户列举的生活服务闭环和可扩展目录，不宣称已经穷尽养老院全部业务需求。
