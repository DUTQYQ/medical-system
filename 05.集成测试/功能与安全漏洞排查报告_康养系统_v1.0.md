## 2. 漏洞清单

### 2.1 严重（可利用 / 数据错误）

**无。** 已重点排除以下项：

- 全部 13 个路由模块的每个 handler 均挂鉴权依赖；admin/config 有路由级 `require_roles`（`app/api/admin.py:17-18`）
- 跨档案访问必经 `get_profile` / `get_service_profile` 越权检查（`app/core/permissions.py:46-65`、`app/services/care_services.py:44-69`），写路径用行锁 + `populate_existing` 规避 MySQL RR 快照旧授权
- 全仓无 `exec` / `eval` / `sqlalchemy.text` / f-string 拼接 SQL（grep 零命中）；LIKE 查询已转义通配符（`admin.py:29-30`）
- JWT 校验要求 sub/exp/jti/epoch 四要素，含 jti 吊销表 + epoch 轮换（`app/core/security.py:40-60`）

### 2.2 中危（逻辑缺陷，建议本轮修复）

#### M1 · 修改登录手机号无需密码验证、不轮换会话
- 位置：`app/api/auth.py:80-92`（`PUT /auth/me`）
- 问题：仅凭有效 token 即可把 `user.phone` 改成任意未注册号码。同文件改密码接口（`auth.py:95-104`）会验旧密码并轮换 `auth_epoch` 使旧 token 全部失效，改手机号却既不验密也不轮换 epoch。
- 影响：手机号是**唯一登录标识**（`auth.py:43`）。会话被盗后攻击者可改绑手机号，受害者既失去登录入口也无法自助找回；且改号后旧 token 继续有效。
- 修复：改手机号要求验证密码（复用 `/auth/password` 流程），成功后 `set_config(db, f'auth_epoch:{user.id}', uuid4().hex)` 强制重登录。**已人工复核属实。**

#### M2 · 家属绑定接口构成老人手机号枚举预言机
- 位置：`app/api/family.py:33-40`（`POST /family/bind`）
- 问题：手机号存在且为启用 ELDER → 建 PENDING 成功；不存在 → 404「老人账号或健康档案不存在」。响应可区分号码是否为注册老人账号。而 `auth.py:20-29` 对任何人开放 FAMILY 自助注册，且无频率限制、无短信验证。
- 影响：任意人注册家属账号后可批量探测手机号，确认哪些是本院老人（"在某康养机构入住"本身即敏感信息），可支撑精准诈骗。
- 修复：`bind` 对"不存在"与"无档案"统一返回模糊文案，接受申请但不激活；对 `/auth/register` 与 `/family/bind` 按 IP/账号加频率限制（可复用 login 的 sys_config 计数器模式）。**已人工复核属实。**

#### M3 · AI 摘要/预警生成链路无配额，可刷 LLM 费用
- 位置：`app/api/health.py:49-66`（每次异常录入都触发 BackgroundTasks 摘要）、`app/api/alerts.py:147-155`（重试无次数限制）、`app/agent/workflow.py:241-274`
- 问题：每日 AI 配额**只统计 `agent='CONSULT_ATTEMPT'`**（`app/api/ai.py:53-61`），而预警摘要走独立通道，落库为 `agent='ALERT'`，不计入任何配额。
- 影响：已认证的低权限用户（ELDER/FAMILY）持续录入异常指标即可无限触发 LLM 调用，FAILED 后还能无限重试 → 成本放大 + 上游限流，影响全院摘要可用性。
- 修复：摘要生成计入统一配额（按 profile 或按触发用户限次/天）；重试接口加冷却或每日上限；同一 profile 的 PENDING 预警可做摘要合并。**已人工复核属实。**

## 3. 项目铁律符合性核对

| 铁律 | 结论 | 依据 |
|---|---|---|
| 1. API Key 绝不进前端、后端 .env 存 | **符合** | 密钥仅从环境变量读取（`agent/llm.py:38-44`）；`.env` 与 `config.local.*` 被 `.gitignore` 覆盖，`git ls-files` 无密钥文件；异常信息 sanitized 不含 URL/key/body（`llm.py:71-73`）；`httpx trust_env=False` 防代理泄露。前端全库搜 sk-/apikey/api_key/硬编码 token **零命中** |
| 2. 健康阈值配置化入表 sys_config，禁止代码常量 | **符合** | 预警判定值全部来自 sys_config（`services/thresholds.py:131-146`，缺配置即 503 fail-closed）；个体阈值走 sys_config 版本链（`services/personal_threshold.py`）；grep 无硬编码健康阈值常量 |
| 3. 预警主流程不得同步等待 AI（D-04） | **符合** | 录入接口同步只建预警（`summary_status=PENDING`），AI 摘要走 `BackgroundTasks`（`api/health.py:63-64`）；摘要超时默认 8s 可配、封顶 30s（`llm.py:54`、`workflow.py:254`），失败降级 FAILED 可重试，另有恢复扫描（`services/recovery.py`）；已实机确认 |
| 4. AI 不得执行任意 SQL、判权限、直写库 | **符合** | `complete()` 纯文本签名，不接收 db/ORM/工具（`llm.py:50-51`）；权限判定全在业务代码；system prompt 明确禁止 + `safe_answer` 输出门（`llm.py:76-84`）；预警由业务函数 `create_warning` 创建 |
| 5. 表名 family_bind / care_relation | **符合** | `models/__init__.py:45,58`，全代码引用一致 |

## 4. 修复优先级建议

1. **F1 录入范围校验** —— 直面数据质量与预警可靠性（三端共用组件，一处修全端受益）
2. **M1 改手机号验密 + 轮换 epoch** —— 会话安全
3. **F3 弱密码校验统一（注册/改密/建号三处）**
4. **F7 通知点击失败阻塞跳转** —— 影响核心闭环体验
5. **M3 摘要配额** —— 控制 LLM 成本
6. **M2 绑定枚举 + 注册限频**
7. 其余低危项按迭代空闲处理；F4（前端补测试）贯穿后续迭代
