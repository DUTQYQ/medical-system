### 1.1 老师在 `shengyadb.xls` 里明确写下的 4 条数据库设计要求（Sheet1）

1. 划分主表和从表，确定主外键关系，**不能所有数据一张表**；
2. **首先确定基础表，再确认业务表**（示例：人员表 → 部门表 → 权限表 → 角色表）；
3. 数据库设计**满足三个范式**（要求自行查阅）。

且数据字典按固定列结构出（见 `admin` 页签）：  
`类型 / 大小 / 名称 / 非空 / 默认值 / 补充 / 描述 / 扩展 / 左表 / 类型 / 右表 / List显示 / 特殊取值描述 / 追加日期 / 追加原因`  
其&#x4E2D;**「左 / 右」两列就是用来表达主外键指向的**。

> `总站会员.dm1` 本机没有 ER/Studio，无法直接打开；但已解出其为 ER/Studio 数据模型（含 Entity / Attribute / PrimaryKey / ForeignKey / Indexes / DbView 段落，图纸名「三亚会员」）。本机已装 **PowerDesigner**（COM 可用），可作为本项目的建模工具。

## 四、Java 口径 → Python/FastAPI 口径映射（防止照抄 demo）

老师模板与 demo 是 Java + MyBatis 口径，我们后端是 **Python 3.11 + FastAPI**，**内容结构照抄、术语必须换**：

| 模板 / demo 写法                     | 本项目对应物                                                |
| -------------------------------- | ----------------------------------------------------- |
| `EmployeeController.java`        | `app/api/v1/alert.py`（`APIRouter`）                    |
| Service 层                        | `app/services/*_service.py`                           |
| Mapper 层（DAO）                    | `app/repositories/*.py`（SQLAlchemy 2.0）               |
| `Constants.java`（订单状态常量）         | `app/core/constants.py`（`IntEnum` / `StrEnum`）+ 状态机取值 |
| `BaseContext`（ThreadLocal 存当前用户） | FastAPI `Depends(get_current_user)` 依赖注入              |
| `R<T>` 统一响应                      | `app/schemas/common.py` 的 `ApiResponse[T]`            |
| `PageResult`                     | `PageResult[T]`（list / total / page / page_size）      |
| DTO / VO                         | Pydantic：`XxxCreate` / `XxxUpdate` / `XxxOut` 三类      |
| `jwt: secret / ttl`（yml）         | `.env` + `app/core/config.py`（pydantic-settings）      |
| MD5 加密                           | **bcrypt**（本机已验证 `bcrypt.checkpw` 回验）                 |
| 健康阈值写成常量                         | 禁止——一律 `sys_config` 表读取（项目铁律 2）                       |

### 7.1 四条新增要求原文口径

| # | 要求 | 老师原话要点 | 对我们的含义 |
|---|---|---|---|
| R1 | **模块划分是第一件事**，且必须分「业务模块 / 技术模块」两类 | "概要设计里面最重要的是模块划分——整个系统分为多少个模块，这是第一件事"；"技术模块…比如数据库访问的呀、或者写日志的呀，这些都是共用的系统功能"；"**技术模块是支撑业务的**" | §2 系统结构图与 §3 必须按**两层**做模块划分，技术模块要单独成块 |
| R2 | 模块粒度灵活，**工程惯例是一个文件一个模块** | "模块粒度有的是大的…比如文件处理模块里边可能有多个不同的类"；"我们一般来讲都是按文件来分模块，一个文件一个模块" | 需在 §3.0 说明"模块 ↔ 文件/目录"的对应关系，证明我们的划分不是随手切的 |
| R3 | **接口 = 被其他模块调用的调用点**，分**外部接口 / 内部接口** | "接口的意思就是被其他模块调用的时候使用的调用形式"；"**外部接口**提供给其他文件调用；**内部接口**是文件或类内部使用的、不对外公开的" | §5.2 每张函数表要能看出**接口性质（外部 / 内部）**；只有 45 个 REST 端点不足以体现"模块间调用" |
| R4 | 确定接口必须明确**三要素：函数名 / 参数 / 返回值** | "一是确定它的名字；第二个是确定它的参数；第三个是确定它的返回值"；"我们用的都是强类型语言…参数固定、签名明确" | 已满足；另：老师明确说**可以借助 AI 工具生成接口设计**，我们的 `_gen/` 生成器正是这条的落地证据 |
| R5 | 数据库交付两条硬指标 | "要求有你创建好的数据库〔脚本〕，还有对应的这个 Excel 文档"；"设计完了之后就能一键〔导出〕，通过它直接创建这个数据库" | ① 可一键建库的 SQL；② 数据字典 Excel；③ 建模工具须支持**正向工程** |
