## 📤 日常工作流程

### 2️⃣ 每天工作前：拉取最新代码

**每天开工前务必先拉取最新代码**，避免和别人冲突：

```bash
# 切换到你负责的分支（通常都是 main）
git checkout main

# 拉取远程最新代码
git pull origin main

# 确认拉取成功
git status
```

> ⚠️ **如果看到 `Your branch is ahead` 说明你本地有未推送的提交**，先推送再拉：
> ```bash
> git push origin main
> git pull origin main
> ```

---

### 3️⃣ 修改文件后：提交 & 推送

#### ✅ 正确流程（推荐）

```bash
# 1. 查看改了什么
git status

# 2. 把所有改动加到暂存区
git add -A

# 3. 提交（写清楚改了什么）
git commit -m "feat: 完成老人端健康档案页面开发"
# 或
git commit -m "docs: 更新需求分析说明书 v1.0"
# 或
git commit -m "fix: 修复 RTM 表格格式问题"

# 4. 推送到远程
git push origin main
```

---

#### ❌ 常见错误

| 错误操作 | 问题 | 正确做法 |
|---------|------|---------|
| `git commit` 没加 `-m` | 会打开编辑器要求写 commit 消息 | 直接 `git commit -m "消息"` |
| `git add .` 而不是 `-A` | 可能漏掉新文件 | 统一用 `git add -A` |
| 没拉直接推 | 可能因为远程有别人提交而失败 | 先 `git pull` 再 `git push` |
| 写模糊的 commit 消息 | 比如 "update"、"修改" | 写清楚："feat: xxx"、"docs: xxx" |

## 📝 Commit 消息规范

我们用简单的约定式提交（Conventional Commits）：

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: 完成 AI 咨询页面布局` |
| `docs` | 只改文档 | `docs: 更新 RTM v1.1` |
| `fix` | 修 bug | `fix: 修复 RTM 表头错位` |
| `refactor` | 重构（不改功能） | `refactor: 整理项目目录结构` |
| `chore` | 不影響业务的改动 | `chore: 删除_build 目录` |

**好消息示例：**
- ✅ `feat: 老人端健康档案新增编辑功能`
- ✅ `docs: 更新需求分析说明书 v1.0`
- ✅ `fix: 修复 RTM 中担当者列空值`

**坏消息示例：**
- ❌ `修改`
- ❌ `update`
- ❌ `test`

## ⚠️ 项目注意事项

### 📄 文档规范

1. **所有 Markdown 文件**（`.md`）是**源文件**，Word（`.docx`）由 `pandoc` 自动生成。
2. **不要直接编辑 `.docx`** —— 改对应的 `.md` 文件，重新转换即可。
3. 如果确实要改 Word（比如封面表格），改完记得同步到 `.md` 里保持内容一致。

### 📂 文件存放

- **只改自己负责部分的文件**，不要碰别人的（除非协同修改）。
- **不要改 `.gitignore`** —— 已经配置好的，误改可能导致某些文件不被追踪。
- **项目目录命名有规律**：
  - `01.` `02.` `03.` ... → 按阶段顺序编号
  - `01-文档` → **不要有**（已删除）

### 🔄 冲突解决

如果 `git pull` 时遇到冲突：

```bash
# 1. 查看冲突文件
git status

# 2. 打开冲突文件，找到 >>>>> 标记
# 手动保留需要的内容，删除 <<<<<<< 和 =======

# 3. 标记为已解决
git add <冲突文件>

# 4. 继续合并
git commit
```

> 如果有疑问，先拉下来看看文件内容，不要盲目覆盖！

### 💾 备份建议

- 每天工作结束前推送一次，避免数据丢失。
- 重要修改后，建议推送到远程。
- Git 会保留历史版本，误删也能从 `git log` 恢复。

## 🆘 常见问题

**Q: 我本地改了文件，但 `git status` 没看到？**  
A: 文件可能被 `.gitignore` 忽略了。检查项目根目录的 `.gitignore`。

**Q: 我想恢复某个文件到上一版？**  
A: 
```bash
git checkout HEAD -- 文件路径
```

**Q: 我误删了文件，还能找回来吗？**  
A: 可以！Git 保留所有历史：
```bash
# 查看文件历史
git log -- 文件路径

# 恢复到指定版本
git checkout <commit-id> -- 文件路径
```

**Q: 推送失败提示 "rejected"？**  
A: 说明远程有别人先推。先 `git pull` 拉最新代码，解决冲突后再推。
