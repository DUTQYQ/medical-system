## 1. 项目概述

### 1.1 项目背景
【用 2~3 句话写：中国老龄化趋势 + 老年人健康管理需求增长 + AI 大模型技术成熟 → 做适老化智能康养平台。可参考网文润色，但必须自己组织语言】

### 1.2 项目目标
- 面向【老年人或其家属】提供【健康数据管理 + AI 健康咨询】的 Web 应用
- 通过调用大模型 API，将用户健康档案数据 + 咨询问题转化为通俗易懂的健康建议
- 界面适老化：大字、高对比、操作路径短、可朗读

### 1.3 建设范围（In Scope）
1. 用户注册/登录（手机号）
2. 健康档案管理（基本信息 + 常用指标录入/查看/修改）
3. AI 健康咨询（对话式，基于档案数据 + 大模型 API）
4. 历史咨询记录查看
5. 管理端：用户管理 + 健康知识/常见问答维护（可选）

### 1.4 非建设范围（Out of Scope，评审必问，提前想好）
- ❌ 不接真实医院/体检机构数据（无接口）
- ❌ 不做紧急医疗报警/医生远程诊断（责任与合规风险）
- ❌ 不做语音识别输入（可后续扩展）
- ❌ 不做移动 App（本期 Web 优先）
- ⚠️ 系统给出的是健康建议/科普，不构成医疗诊断——需在页面声明

## 4. AI 智能体需求（评审重点，写清楚实现思路）

### 4.1 技术路线
- 选用国内大模型 API：**【候选：DeepSeek / 通义千问 / 智谱GLM——请组内定一个】**
- 实现方式：后端服务封装 prompt（系统提示词 + 用户档案摘要 + 问题）→ 调用 API → 返回并展示
- 不训练/微调模型；不本地部署（成本高、组内零基础）

### 4.2 提示词策略（草案）
- 系统角色设定："您是面向老年人的健康助理，回答通俗、简短、有同理心，不使用专业术语堆砌；涉及就医建议时提醒咨询医生"
- 输入：结构化档案摘要（年龄/性别/血压/心率/慢病）+ 用户问题
- 输出：分点建议 + 风险提示 + 鼓励性结尾

### 4.3 风险与对策（写进文档=加分项）
| 风险 | 对策 |
|---|---|
| AI 输出幻觉/不当医疗建议 | 系统提示词限定范围 + 页脚免责声明 + 预留敏感词过滤 |
| API 费用/限流 | 选低价模型；单次回答限字数；控制调用频率 |
| 老人不会打字 | 预设常见问题按钮（血压高怎么办/降压药几点吃好等） |

## 5. 非功能需求

| 类别 | 要求（草案） |
|---|---|
| 性能 | 页面响应 < 3s；AI 回答（流式可选）可接受 5~15s |
| 安全 | 密码加密存储（bcrypt）；登录态 token；仅本人可看本人档案 |
| 可用性（适老化） | 默认字号 ≥ 16px；对比度达标；按钮大（≥44px）；主流程 ≤ 3 步；可一键朗读 |
| 兼容 | Chrome/Edge 现代浏览器即可 |
| 数据备份 | 数据库定期导出（开发期每周） |
