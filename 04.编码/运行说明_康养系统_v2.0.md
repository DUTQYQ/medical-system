# 康养系统养老院业务运行说明

版本 2.0，日期 2026-10-14。当前四角色前端增加主动问询、个人词条、易读建议、个体阈值，以及院内服务工单、活动报名、呼叫和设备借还。本文用于团队启动、演示与联调，需与《养老院业务扩展说明》和验收记录一起使用。

## 数据库升级与启动

本机配置仍位于 `04.编码/后端/.env`，真实密码和模型 Key 只保存在后端。现有 MySQL 采用增量迁移：原十五张表保留，扩展表共十五张，2026-10-14 新增测量作废审计表。只追加缺少的服务目录、呼叫超时、数据新鲜度及可选摘要请求额度配置，真实库没有生成演示活动或虚构设备库存。

其他成员升级现有 v1 数据库，在后端目录先预览：

```powershell
.venv/Scripts/python.exe -m scripts.migrate_v2
```

应用增量迁移：

```powershell
.venv/Scripts/python.exe -m scripts.migrate_v2 --apply
```

脚本先将旧表完整数据备份到本机忽略目录 `config.local.migration-backup`，再创建缺少的扩展表，校验原表行数，并追加缺少的服务默认项。重复执行不重复建表或覆盖已有配置。已存在扩展表的列、类型、主键、唯一键或外键不符时拒绝隐式改表。备份含敏感资料和密码哈希，不进入 Git。

SQL 评审稿为数据库目录 `migrations/002_养老院业务扩展.sql`。该稿供一次性建表评审，索引语句不能反复导入；日常升级使用 Python 幂等迁移。不要为升级重新执行旧 `schema.sql`、初始化 SQL 或完整备份，因为旧脚本包含清理表操作。

项目根目录启动正常模式：

```powershell
& './一键启动.ps1' -Background
```

演示使用独立 SQLite：

```powershell
& './一键启动.ps1' -Demo -Background
```

答辩启动根目录 `一键演示多窗口.ps1` 会在 8001 / 5174 使用独立演示库并打开四个隔离登录窗口。执行 `一键停止.ps1 -StateName demo` 只停止演示服务。

启动脚本核对服务标识、源码版本、数据库模式和前端代理。受本脚本管理的后端代码变化时自动重启；复用时保留原进程编号及启动时间，因此再次启动后仍能一键停止。未管理的不同模式或旧版本进程不会被自动结束，会提示停止原进程或改用端口。后端直接启动 Python，按模式分别记录日志，进程退出会立即报告。修改 `.env` 配置后须先停止再启动，因为配置内容不进入公开源码指纹。正常模式默认 8000/5173，`-Demo` 默认 8001/5174 并保存 `demo` 状态；`-ApiPort` 同时设置前端 `/api` 代理。

## 账号与权限

独立演示库四账号依次为管理员 `13000000001`、老人 `13000000002`、家属 `13000000003`、护工 `13000000004`；初始密码 `Abc123456`。这些账号及演示资源仅用于演示库，真实库沿用原有账号。健康数据、咨询词条和阈值首次使用需在个人中心确认健康授权；生活服务及呼叫仅校验身份和当前照护关系，可独立使用。

老人和已绑定家属可申请服务、报名活动、申请设备及查看进度；护工管理负责老人的任务、记录出席和归还、提交个体阈值调整；管理员维护资源、服务目录、照护分配并审核阈值。解除绑定或照护关系后旧通知不会维持访问权限。

## 建议的答辩演示

1. 老人第一次打开康养助手，自动出现第一题。选择喜欢打牌、需要陪同等实际演示信息，完成或跳过六题，确认保存词条。刷新后仍能看到确认信息。
2. 生成生活建议卡，检查四个分区、个人事实及生成方式。无模型 Key 时明确显示规则建议，问卷、词条及服务功能照常可用。
3. 点击娱乐建议，只预填生活服务申请。核对老人、地点及具体需求后提交。护工进入任务台接单、开始处理、填写完成结果；老人查看过程和通知。
4. 工作人员发布未来的棋牌活动，老人报名；演示满额拒绝和取消后名额释放。活动开始后由工作人员登记出席。
5. 管理员录入真实设备及可用总量。老人申请借用，护工接单扣库存；归还恢复可用量，损坏归还转入损坏数量。重复归还不会再次增加库存。
6. 老人填写地点并呼叫工作人员。重复点击复用未完成呼叫，护工任务台优先显示；没有负责护工时管理员立即收到通知。
7. 护工打开所负责老人的个体阈值页，填写理由和完整范围；管理员审核后生效。先前测量和预警保留原检测快照，新录入使用个体配置，另一档案仍使用自身配置。

独立演示数据只用于软件逻辑验证，演示阈值和活动安排不能作为个体医疗判断。页面带“健康建议不构成医疗诊断”。

## AI 配置与业务后台

国内模型由后端 `.env` 的 `LLM_PROVIDER` 选择 deepseek、qwen 或 glm；修改 Key 后需重启后端。真实模型效果、延迟和成本需单独验收；默认哈希 Embedding 只做词形检索。

院内呼叫后台默认每十五秒扫描；`SERVICE_DISPATCH_ENABLED=false` 可关闭。待接单升级秒数保存在 `sys_config.service_call_timeout_seconds`，默认三百秒；任务台和通知请求也会触发检查。站内调度不能替代现场值班或硬件按钮。

## 2026-10-14 功能边界更新

更换登录手机号或密码时，须在个人中心填写当前密码，成功后重新登录；手机号和密码可以同时保存，避免旧登录先失效导致密码修改未完成。服务、借还、健康录入和个体阈值页面切换老人后会重置对应表单，旧响应不会覆盖新页面。

删除档案前须完成或撤回服务、归还设备、结束或取消报名，并核验待处理预警；有未结事项时页面显示数量。测量作废不会自动解决原预警，也不会继续发布基于该错误测量的 AI 摘要。

可选摘要默认全院每日 100 次、单条每日 3 次、手动重试间隔 60 秒，配置保存在 `sys_config`。失败请求同样计入额度，原预警和处理不受额度限制。健康录入范围仍由管理员依据采集设备和院方要求配置，前后端使用同一范围，不把输入范围当作医疗判断阈值。

前端延迟响应和表单回归可在前端目录执行 `node --test ../../05.集成测试/前端浏览器/ai-state-regression.cjs ../../05.集成测试/前端浏览器/workflow-state-regression.cjs`。这是实际页面函数回归，不等同于完整浏览器视觉验收。
