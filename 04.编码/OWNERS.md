# 04.编码 · 文件所有权表

> 本文件是避免 Git 冲突的**核心约定**，编码开始前全员必须读完。
> 一句话原则：**属于你的目录随便改，别人的目录一眼都别碰。**

---

## 为什么要有这张表

很多人以为"开了分支就不会冲突"——这是误解。分支只是把冲突**推迟**到合并的那一刻，并不会让它消失。

真正让三个人互不干扰的是**物理隔离**：只要两个人永远不修改同一个文件，Git 就永远不会报冲突。

所以本表规定的是"谁能改哪些文件"，这比任何 Git 技巧都重要。

### 路由分文件规则（重要）

三人各做各的页面，如果都往 `router/index.js` 里加路由，**每加一个页面就会冲突一次**。

解决办法：`router/index.js` **只负责 import，不写任何具体路由**。

```js
// router/index.js —— 只允许出现 import 语句，不允许手写路由配置
import elderRoutes from './elder'
import familyRoutes from './family'
import careRoutes from './care'
import adminRoutes from './admin'

const routes = [...elderRoutes, ...familyRoutes, ...careRoutes, ...adminRoutes]
```

每人只在自己的 `router/xxx.js` 里写路由，从此不再冲突。

## 三、需要改别人的文件时怎么办

优先级从高到低：

1. **先问**：在群里说明要改哪个文件、改什么，让归属人确认
2. **归属人代改**：小改动直接请归属人帮忙提交
3. **自己改**：归属人同意后，改完立刻提交并 push，通知对方 pull，避免两人同时停留在这个文件上

**严禁**：不打招呼直接改别人的文件并 push。

## 四、接口层协作约定

前端 `src/api/` 目录由丘宇乾维护，但梁霁鸣与周彦龙是使用者。约定：

1. 接口契约先写入 `03.概要设计/API接口契约_康养系统_v0.2.md`
2. 丘宇乾按契约实现后端，并在 `src/api/` 提供前端调用函数
3. 前端只调用 `src/api/` 暴露的函数，**不在页面里手写 axios 请求**
4. 接口需要变更 → 先在契约文档里改，双方确认后再改代码

这样即使后端还没写完，前端也能按契约先用 mock 数据开发，不必干等。
